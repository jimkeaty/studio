## Current Behavior Inventory

### Agent lifecycle and selectors

`/api/broker/active-agents` is the current lifecycle-oriented headcount source. It excludes `inactive`, `out`, `terminated`, and `churned` from active counts, counts explicit departure statuses only when an end date exists, and maintains a separate Inactive review list. It treats grace agents as a separate population from established active agents.

`/api/admin/agents?source=profiles` conflicts with the locked default-selector rule: it appends `grace_period`, `inactive`, and `out` profiles to an otherwise active list. Its `source=rollups` fallback has no lifecycle filter. SBUSA-011 must preserve the Transaction Ledger historical lookup exception while making ordinary selectors Active-only.

### One-on-one assignments and report-card eligibility

The DAD report-card API independently derives four coverage lists from `agentProfiles`, `oneOnOnes`, and `transactions`: new agents in the first 90 days, agents under one year, agents with no year-to-date closed/pending activity, and all active agents for quarterly strategy meetings. It currently uses a **year-to-date** closed-activity test plus current pending status for the no-production category, not the locked rolling inclusive 60-day test.

The one-on-one API persists individual meetings but does not calculate which agents should receive which operating meeting type. This is the core duplicated eligibility logic SBUSA-002 must centralize.

### DAD scorecard and director activities

The DAD scorecard reads `recruitingPlans`, `agentProfiles`, `oneOnOnes`, `directorDevelopmentActivities`, `agentAttendance`, and `transactions`. It currently scores sales meetings, huddles, role play, training sessions, training attendance, call-night hours, and new-agent follow-ups alongside the intended development and recruiting measures. These remain valid historical activities but conflict with SBUSA-003, SBUSA-006, SBUSA-012, and SBUSA-016 scoring requirements.

The scorecard currently uses monthly goals multiplied by months elapsed rather than a later-of-January-1-or-effective-start-date pacing basis. Goals and scoring are also surfaced by the DAD component, recruiting metrics endpoint, and broker business-plan workflow.

### Attendance and floor time

The shared attendance rules use `America/Chicago` and define the current QR events: mandatory Tuesday/Thursday huddles, optional Tuesday/Thursday training, optional Wednesday sales meeting, and mandatory Wednesday role play/New Agent IDS. Floor time requires two qualifying three-hour weekly shifts and one qualifying four-hour weekend shift each month.

The agent attendance API writes scheduled-event QR scans and secure geofenced floor-time check-in/check-out rows to `agentAttendance`. It has no Floor Time QR event, no admin enable/disable state for a floor-time code, and no independent Director-of-Agent-Development SMS attempt or delivery audit. SBUSA-010 must extend this existing system rather than create a competing attendance store.

### Recruiting, welcome calls, and pipeline status

Face-to-face recruiting meetings are currently stored as `directorDevelopmentActivities` with activity type `in_person_relationship_meeting`, while recruiting follow-up activity is also stored in `recruitingPipelineActivity`. DAD uses `new_agent_welcome_call` as a distinct activity type, but recruiting goals and labels still overlap. SBUSA-005 must separate recruiting prospect contacts from onboarding welcome calls without deleting either history.

The recruiting pipeline currently contains both `scheduled_start` and `started`; on GET, a past expected start automatically changes a candidate to `started`. This conflicts with SBUSA-008, which requires a past scheduled date to remain Scheduled Start with a verification warning until an actual start date or active status is confirmed.

## Baseline Regression Priorities

1. Lifecycle classification at effective dates: Active, Inactive, Out, archived lookup, and Transaction Ledger historical exception.
2. One-on-one eligibility boundaries: day 1, day 90, day 91, inclusive 60-day production/pending lookback, missing dates, and no duplicate category assignment.
3. Attendance opportunity denominator boundaries: team entry, inactive date, no eligible events, and Central-time event windows.
4. Recruiting pipeline Scheduled Start versus Started transitions: expected date alone, actual start, and active-profile confirmation.
5. Call-night duration thresholds and appointment threshold bands.
6. Floor-time QR check-in record, notification attempt, and delivery outcome separation.
7. Start-date-adjusted pacing and explicit Threshold Not Configured behavior.
